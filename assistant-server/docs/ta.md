# 助教作业批改

入口为 `/ta`，也可从全站导航的“助教批改”进入。页面沿用课程回放批量处理的配色、页头、插画与课程侧栏。

打开页面先显示框架和加载占位，课程与作业通过 `/api/ta/workspace` 在后台读取。刷新、筛选、切换课程或提交、保存草稿和同步结果只更新下方工作区，不重新加载页头。加载失败可以局部重试，写入请求不会自动重发。

## 使用

1. 使用现有小助手账号登录。在用户中心完成已有的教学网绑定后，页面自动读取 `TeachingAssistant` 角色的课程；本模块没有独立登录或绑定表单。
2. 选择作业，可按批改组、评分状态、姓名或学号筛选。默认每位学生只展示最新提交，勾选“显示历史提交”可逐次查看。
3. 查看提交正文、下载附件或展开 PDF 预览，填写分数和评语。“保存并批改下一份”将本份保存为本地草稿并打开下一份。
4. “快速批改”支持选中提交统一给分、统一评语、满分草稿，也可选择当前筛选下的全部可评分提交，每次最多 200 份。已评分提交需要显式允许修改，豁免和提交中的记录不可评分。
5. 在“核对并同步”中勾选草稿，确认后写入教学网对应的具体提交。每份登分后回读核验分数，发生变更或失败即停止，其余草稿保留。

保存草稿不会修改教学网。登分结果未确认时会标记“需核对”并阻止直接重试；应先在教学网核对，再丢弃旧草稿或重新批改。

## 实现

- `src/services/ta.rs`：Rust 教学网客户端，共用回放的 curl 执行器，实现分页、角色识别、附件解析、nonce 和登分回读。
- `src/routes/ta.rs`：页面路由、会话获取、按账号隔离的持久草稿、批量操作和附件代理。
- `src/routes/ta_view.rs`：Rust 生成的 HTML、CSS、表单及内嵌的局部更新浏览器脚本。复用现有公共样式及资源，无新的前端构建或依赖包。

优先从 `AppState.login_cache` 获取已有教学网会话；缺少缓存时调用现有 `pkulogin::login_iaaa_and_get_cookies_with_cache`。直接将现有 Netscape Cookie 文件交给回放共用的 curl 执行器读写，不再导入另一套 Cookie jar；业务逻辑全部用 Rust，不调用 Python 或 pku3b，不新增登录组件。助教和教学网回放共用下述单次登录策略。

教学网会话保存在服务数据目录的 `teaching_sessions/`，包括 Cookie jar、User-Agent、账号与原始登录时间，服务启动时自动恢复，正常退出不删除有效会话。仍按原始登录时间执行一小时有效期，重启不延长有效期；失效、解绑和替换会话会清除持久缓存，正在运行的请求保留文件租约直到结束。curl 直接更新持久 Cookie 文件。部署时需持久挂载服务数据目录；此目录包含登录凭据，应仅允许服务账号访问。IAAA 一次性票据和密码不写入该缓存。

新建教学网登录会话只执行一次完整 IAAA 登录、一次性 token 回调和教学网门户验证；任一步失败立即返回错误，不自动重试。UA 从原有 `user_agents.txt`（没有可用项时回退到 `.gz`）随机取一个有效值，不按平台或登录成败筛选，不删除或修改原池，也不读取或维护成功池。有效的现有会话直接复用，不因 UA 平台重新登录。

评分状态以教学网的提交状态为准：`NeedsGrading` 等未批改状态即使返回数值 `0`，也显示为待评分且不预填零分；`Completed`／`Graded` 状态下真正给出的零分仍显示为已评分。Blackboard 官方也说明了[未批改状态可能带有零分](https://help.anthology.com/blackboard/instructor/en/original-course-view/tests%2C-pools%2C-and-surveys/grade-tests.html)。

页面只用 GET 浏览和 POST 表单进行修改。修改请求校验当前登录会话派生的 CSRF 凭据，并在服务端重新校验助教身份、作业、提交记录、分数范围和提交版本。草稿通过现有 FileStore sidecar 接口存入 SQLite，键按用户 UUID、课程和作业隔离；登分前持久化操作标记，避免服务中断后未经核对地重复登分。

附件代理仅接受当前助教课程中真实提交页面返回的文件；请求及重定向限制为教学网同源。附件大小上限为 32 MiB，大文件提供教学网原始提交入口。PDF 按扩展名及文件头校验后支持预览，其他附件强制下载。

## 验证与范围

助教 HTTP 请求与教学网回放共用 `pkulogin::run_curl_bytes`，复用缓存 Cookie 文件、文件锁和 User-Agent，并沿用回放的 curl 参数与超时设置。评分表单写入临时文件后提交，不自动重发 POST。无需新增 Rust TLS 后端、OpenSSL 库或构建工具。

后台 `teaching_ta` 日志在 info 级别记录请求和响应状态，在 warn 级别记录经过脱敏的底层连接错误。日志不输出 Cookie、nonce、请求体、查询参数或学生标识。curl 连接错误、HTTP 登录过期和权限拒绝会分别显示。

可手动检查公开接口连通性，此测试不携带账号、密码或 Cookie，也不会登分：

```text
cargo test --offline teaching_curl_smoke_test -- --ignored --nocapture
```

```text
cargo test --offline '::ta::'
cargo test --offline protected_html_requires_valid_session_before_rendering
```

本地视觉预览使用虚构数据，不会访问教学网：

```text
cargo test --offline ta_visual_preview -- --ignored --nocapture
```

随后打开 `http://127.0.0.1:18192/ta`。该测试预览不提供登分操作，最多运行 15 分钟。

真实教学网权限、课程配置和页面结构可能不同，尤其是非标准作业、匿名/委派批改和不支持 reconciliation 的成绩列。首次使用需用真实助教课程验证读取和单份登分；模拟测试不能替代实网联调。不包含 Word 预览或 PDF 内页批注。

## AI 自动批改

选定作业后展开“AI 自动批改”，由助教手动输入完整题目，可补充参考答案与评分标准。复用用户中心/服务端现有 DeepSeek 密钥与 API 地址；教学网仍使用现有 curl 与缓存 IAAA 会话。没有新增依赖或 OpenSSL。文档输入固定使用支持 Files API 的 `deepseek-flash`，不使用用户配置中可能不支持文档的旧模型。

每位学生只处理最新一次提交，所有题目、正文和附件合并为一次 Chat Completions 请求，不逐题调用。PDF、Word 和幻灯片通过 Files API 的 `rich_layout_recognition` 解析，保留检测到的图表；PNG/JPEG 等图片通过 `user_data` 输入。每个附件需单独上传解析（也会产生 API 用量）。不自动重试上传或批改，以免重复计费。支持 UTF-8 文本与常见代码文件，不执行学生代码。超过 20 个附件、附件超过既有下载限制（32 MiB）、空白或无法判读的材料交由人工处理，不截断材料后评分。不支持的附件跳过下载和上传，继续处理支持的材料，并列出跳过的文件供人工复核。若模型返回 needs_review=true 或 has_work=false，保留其参考分数（无有效分数则留空）、评语与复核原因，在任务面板显示并可载入当前提交的评分表单，核对后手动保存为草稿，不自动补 0 分或象征性保底分。解析服务不保证识别所有图，助教须核对原始 PDF。

- 严格评分：根据正确性和教师标准打分，范围为零至教学网所设满分。
- 象征性评分：有实质作答时按独立错误题目/小题计数，每处扣满分的 1%，最多扣 10%；公式由 Rust 服务端执行，分数保留两位小数。满分来自教学网，未固定为 10。空白、无关或不可读材料不自动获得保底分。
- 两种模式评语均简洁具体，提示模型写 2—4 句、约 50—150 字（返回超过 300 字则标记失败），指出关键问题和可执行的改进。

后台“助教批改 → AI 评语标记”（`/admin#ta_ai`）可开启/关闭末尾标记并编辑纯文本格式，默认“本评语由 AI 生成。”，支持 `{model}` 和 `{mode}`。设置由管理员权限与现有后台请求校验保护，SQLite sidecar 持久化；任务启动时快照设置，新设置不改写已有草稿。

任务后台运行，进度单独轮询，不刷新整个页面；同一用户同时只能运行一个任务，全站最多两个任务同时处理。范围为整份作业，不受当前分组或筛选影响；默认跳过教学网已评分提交，可显式勾选包含。已有草稿（含已同步/同步未确认的草稿）、免评和作答中提交均跳过。保存前重新核对最新提交、版本、满分与人工草稿，避免覆盖并发编辑。AI 仅创建本地评分草稿，必须由助教核对、手动确认同步，不直接登分。

支持取消（等待当前请求返回并清理后停止），服务重启显示任务中断，保留已生成草稿。连续三次 AI 接口/输出异常或密钥/额度/限流错误会停止任务，显示逐份失败原因；个别空白、不可读或不支持的材料不会阻止其他学生的批改。上传时使用匿名文件名，不向 DeepSeek 发送教学网凭据；作业正文自身可能含身份信息。每份处理结束删除本任务上传的临时文件，并设置一小时过期作为异常情况下的兜底。状态、教师题目和失败项按用户与作业隔离持久化，不保存原始附件、密钥或推理过程。

相关测试（使用本地模拟接口，不使用真实密钥）：`cargo test --offline ta_ai`。
