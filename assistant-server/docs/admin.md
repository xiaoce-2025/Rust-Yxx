# 管理后台

后台入口为 `/admin`，使用现有站点登录会话。布局参照 Django Admin：全宽顶部工具栏与面包屑、左侧应用/模型导航、模型目录、数据列表及独立的记录编辑页。白底与灰色分隔线，沿用站点字体及品牌文字色，不提供数据总览、统计卡片或欢迎区。

## 开通管理员

1. 正常登录已有账户，在 `/api/auth/me` 中查看该账户的 `user_id`。
2. 在服务实际加载的环境配置（例如 `config/production.toml`）中加入：

   ```toml
   [admin]
   user_ids = ["这里替换为账户 UUID"]
   ```

3. 重启服务。该账户右上角的账户菜单会显示“管理后台”，也可直接访问 `/admin`。

默认列表为空，普通用户不能访问后台页面和接口。多个管理员可填写多个 UUID。撤销管理员权限时从配置中移除对应 UUID 并重启。此后台管理的是小助手本身，不包含外部统一认证中心的账户管理。

## 功能

- **站点管理**：按“认证和授权”“课程回放”分组列出模型入口。
- **用户**：搜索、右侧状态/管理员筛选、列排序及分页；点击用户名进入独立表单，更改启用状态、存储配额、处理配额及优先级（1–100，越小越优先）；支持保存、保存并继续编辑及撤销其他用户的会话。列表可勾选记录，批量启用、停用或撤销会话；无法停用管理员或撤销自己的会话。身份资料只读。
- **课堂笔记任务 / 回放中转任务 / 视频翻译任务**：各自独立的模型列表，按用户或任务 ID 搜索、按状态筛选，点击任务查看完整 ID、所属用户及时间等字段。状态由处理流程维护，此处只读，不提供删除、重试及下载。
- **注册白名单**：邮箱记录列表，支持搜索、排序、分页，以及单条添加、更改、删除和勾选批量删除。保存到 `data/whitelist.json`，刷新或重启后仍保留。邮箱大小写与已有认证逻辑保持一致。空名单会阻止注册及统一认证登录；已有本地账户登录不受白名单变更影响。

后台数据接口为 `/api/admin/data`，列表按需刷新。批量动作仅操作当前页勾选记录；跨多条用户记录的动作逐条执行，失败时显示已完成数量。修改用户优先级只影响后续提交的任务；停用用户会阻止后续认证请求，已经开始的后台任务继续运行。配额单位与现有应用一致。

所有后台 API 均校验有效会话与服务端管理员名单，写入还要求 `X-Admin-Request: 1` 请求头。页面与接口返回 `Cache-Control: no-store`，响应不包含用户密码哈希、API Key、登录令牌、视频来源 URL 或本地文件路径。

## 验证

```powershell
cargo test routes::admin::tests --offline
node --test tests/admin_ui.test.cjs
```

测试涵盖未登录/普通用户拒绝访问、写请求校验、参数校验、用户配额更新、管理员停用保护、白名单校验与重复覆盖写入、会话撤销、停用账户及重载持久化。前端测试覆盖模型目录、搜索/筛选/排序/分页、跨页选择隔离、文本转义、任务分类、表单保存和批量动作确认。
