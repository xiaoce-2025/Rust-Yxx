## 一、功能目标

在现有 `pkuvideo_fw` 页面增加英文课程视频自动翻译和中文配音功能：

英文课程视频 → 外部 ASR → 中文翻译 → 云端 TTS → 自动对轴 → 中英文字幕 → 中文译制视频。

具体要求：

- 服务器没有 GPU，使用云端 AI 服务和本地 CPU 音视频处理。
- 现有 ASR 已支持时间戳及 `language_hints`，优先复用。
- 当前 ASR 不返回说话人信息，不需要额外引入说话人识别。
- 英文翻译为简体中文。
- 配音使用自然的中文合成音色，无需音色克隆。
- 保持原视频画面、播放速度和总时长不变。
- 支持原声、中文配音、中英文字幕切换。
- 功能仅用于 `pkuvideo_fw`，不得影响既有统一视频处理流程。
- 支持长课程、任务进度、缓存、断点续跑和失败重试。

## 三、关键技术路线

初步倾向于：

**VideoLingo 翻译及字幕处理思路 + 语义块 TTS + 独立固定时间轴对轴引擎 + FFmpeg。**

但这只是候选方案，请根据源码和实际部署条件评估，不要预设它一定最优。

### TTS 设计

重点考虑 Azure Neural TTS，同时对比其他云端 TTS 服务。

采用约 5–15 秒的语义块分段生成，而不是整节课程一次合成。具体片段长度应根据语义、停顿和实际测试调整。

需要评估：

- 中文语音自然度。
- 不同请求之间的音色稳定性。
- SSML 或其他语速控制能力。
- 是否能够指定目标时长。
- 是否返回词级或句级音频时间戳。
- API 并发限制、价格和可靠性。

TTS 提供商应通过统一接口封装，方便后续更换。

### 自动对轴

这是核心功能。

每个配音块有原始时间窗口，TTS 生成后需要测量实际音频长度。

优先通过合理利用原声停顿来安排配音。

当译音超出时间窗口时：

1. 尝试小幅调整语速。
2. 必要时让 LLM 压缩中文译文。
3. 重新合成并测量长度。
4. 仍无法合理对齐时记录异常，不得无限重试。

必须避免全局累计时间漂移。

不允许为了对轴而改变原视频播放速度。

### 字幕

需要同时生成：

- 英文原始字幕。
- 中文翻译字幕。
- 与最终中文配音同步的中文字幕。

请特别分析：采用语义块 TTS 时，如何得到块内部的精确中文字幕时间戳。

比较直接使用 TTS 的 WordBoundary、额外执行强制对齐，以及按片段时间分配等方法的准确性和成本。

### 音视频封装

优先采用 FFmpeg。

尽可能使用 `-c:v copy`，避免 CPU 重新编码视频。

评估：

- 原始英文音轨的保留方式。
- 中文配音作为第二音轨的封装方式。
- MP4 内嵌软字幕与独立 WebVTT 的优缺点。
- 当前 `pkuvideo_fw` 播放器的兼容性。
