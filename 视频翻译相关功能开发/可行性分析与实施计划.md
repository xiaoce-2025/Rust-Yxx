# pkuvideo_fw 视频翻译：可行性分析与实施计划

日期：2026-10-20。状态：已获准开发，首版代码已接入；服务器媒体与云接口联调待完成。

实施约束更新：用户已同意开始开发，后端只使用 Rust 及 Rust 库，并调用服务器已有 FFmpeg。不新增 ffprobe、Python 或其他外部运行依赖；本地不测试 FFmpeg。该约束覆盖下文早期方案中对 ffprobe 及 Python 对齐器的建议。当前实现与配置见 `assistant-server/docs/video_translation.md`。

## 1. 已确定的需求与边界

以本次对话要求为准，覆盖《开发目标.md》中早期的 Azure 优先设想。

- 英文课程翻译为简体中文，ASR 固定使用现有方案 Paraformer-v2，翻译使用现有 DeepSeek，配音新增 MiMo `mimo-v2.5-tts`。
- 仅在 `pkuvideo_fw` 下载完成后增加“视频翻译”入口，翻译是独立附加任务。现有下载、登录、单用户任务槽位、统一视频处理、讲义生成等工作流保持原有设计。
- 翻译成功后，当前播放器自动切换到中文配音视频；支持切回原声以及选择英文、中文、双语或关闭字幕。
- 下载区改为“下载原视频”和“下载翻译视频”。后者仅在成品发布后可用；翻译前、翻译中、翻译失败均可继续播放和下载原视频。
- 删除任务时，取消相关翻译处理，删除原视频、翻译视频、识别结果、字幕、配音片段和缓存。现有手动回放替换旧任务时，也通过统一清理入口清理其翻译内容。
- 保持原画面、播放速度和总时长；无 GPU；不新增说话人识别、音色克隆或背景人声分离。
- 支持长课、阶段进度、按块缓存、失败重试及服务重启后续跑。

标注约定：**[源码]** 表示已阅读本仓库或上游实现；**[文档]** 表示文档描述；**[设计]** 表示本计划建议；**[待实验]** 表示尚未通过真实接口或媒体验证。

## 2. 可行性结论

**可行，推荐 Rust 独立翻译模块 + 三个云端服务 + 本地 FFmpeg/ffprobe。** 本阶段不建议把 VideoLingo、pyVideoTrans 或 SoniTranslate 整套部署进现有服务。

主要难点在于译音时长约束、MiMo 未在所提供文档中说明的句词时间戳能力、长课恢复，以及删除与后台任务之间的竞争。固定原视频时间轴意味着：少数特别密集的内容可能无法在自然语速下完整容纳，必须允许有限次压缩译文，并将仍然失败的块标为待处理，不能截断讲话或将画面慢放。

“保留总时长”以原始媒体时间轴及视频包时间戳为基准；AAC 编码存在帧粒度和 priming/padding，需要实际验收封装时长及播放器行为，不能宣称所有容器字段逐毫秒完全相等。

## 3. 当前仓库的真实接入点

以下路径相对于仓库根目录。

### 页面与原视频

- **[源码]** `assistant-server/templates/pkuvideo_fw.html`：原生 `<video controls>`，`renderJob()` 在下载成功后创建播放器和下载、删除按钮；没有现成字幕或音轨切换组件。
- **[源码]** `assistant-server/src/routes/pkuvideo_fw.rs`：已有提交、手动回放、任务列表/详情、删除和视频 Range 响应。原视频地址为 `/api/pkuvideo_fw/jobs/:id/video.mp4`。
- **[源码]** 下载入口限制每个用户一个任务槽位；`submit_manual_replay()` 会通过 `remove_job()` 删除该用户旧终态任务。该行为保持不变，仅扩展清理范围。
- **[源码]** `assistant-server/src/services/pkuvideo_fw.rs`：只负责下载及下载任务模型。传统来源保存到 `./data/pkuvideo_fw_jobs/{timestamp}_{job_id}/video.mp4`，手动回放来源保存到 `./data/pkuvideo_fw_jobs/{job_id}/video.mp4`。
- **[设计]** 新模块必须读取 `job.video_path`，不能假设所有视频目录均为 `{job_id}`。

### ASR 和大模型

- **[源码]** `assistant-server/src/services/pkuvideo.rs` 已实现抽音频、上传 OSS 临时资源、提交 Paraformer 异步任务、轮询、下载结果。当前 `speech_to_text()` 最终只保存纯文本，不适合直接作为新功能的时间轴输入。
- **[源码]** 现有 ASR 提交函数只设置 `channel_id`；虽然供应商支持时间戳和 `language_hints`，当前这层请求没有传 `language_hints`，下载解析也没有保留 `sentences/words`。
- **[设计]** 保留旧函数及旧输出约定，新增翻译专用 ASR 适配器，沿用相同服务、凭证和上传方式，完整保存响应 JSON。英文识别用 `language_hints=["en"]`；可配置时间戳校准，具体效果先验证。
- **[源码]** DeepSeek 现有实现用于生成讲义，依赖 `system_prompt.md`；新任务只复用供应商配置与请求方式，使用独立翻译提示词，绝不调用讲义生成流程。
- **[源码]** `src/config.rs`、`src/routes/user_api_config.rs` 和 `FileUserConfig` 已有阿里云、DeepSeek 配置。新模块解析这些配置，保持既有凭证优先规则；既有调用先读取对应环境变量，随后才使用已合并配置。新模块固定要求 `paraformer-v2`，不修改用户在其他工作流中的模型选择。

### 后端、持久化和部署

- **[源码]** Axum 0.7、Tokio、reqwest；`AppState` 保存内存任务，实际业务通过 `FileStore` 保存 JSON。不能因 Cargo 中声明了 SQLx/PostgreSQL、Redis 就假设本功能已有数据库任务队列。
- **[源码]** `src/main.rs` 加载任务，`AppState::load_pkuvideo_fw_jobs()` 只恢复记录，不恢复执行；当前后台下载使用 `tokio::spawn`。新任务需独立实现恢复策略。
- **[源码]** 已有 FFmpeg 命令调用，但现有 `extract_mp3()` 失败时会写占位内容。新任务不复用该失败语义，新增严格抽取与媒体校验，失败立即停止新任务，旧流程原样保留。
- **[源码]** 未发现仓库中的 Python 服务、Python 依赖清单或容器部署文件；有 `assistant-server/deploy.sh`。第一版不新增 Python 常驻进程、GPU 或 Redis 队列依赖。
- **[待实验]** 本机 PATH 检查未找到 FFmpeg/ffprobe，不能据此推断生产服务器情况。开发原型前检查目标服务器二进制、版本、AAC/atempo 支持、磁盘、内存及云接口连通性。

- **[设计]** Paraformer 词级结果可以经适配后进入相似的下游数据结构，但未验证有直接导入原始 Paraformer JSON 的通用入口。首版在 Rust 中参考其设计，不制造 Excel 中间层。

## 5. MiMo 接入方案与能力边界

**[文档]** 以同目录《语音合成供应商mimo文档.md》为接入依据：

- `POST https://api.xiaomimimo.com/v1/chat/completions`，`model=mimo-v2.5-tts`。
- 待朗读内容放在 `assistant.content`；可选 `user.content` 提供稳定的普通话课程讲解风格指令。
- 首版使用非流式 WAV，解析 `choices[0].message.audio.data` 的 Base64 后保存并校验。流式 PCM16、24 kHz 单声道作为后续优化，不是首版依赖。
- 使用明确中文 voice，例如“苏打”作为待试听的默认值，或“白桦”“冰糖”“茉莉”。不使用会随集群变化的 `mimo_default`，全课程固定 voice 和风格模板。
- 文档描述自然语言语速控制，但没有给出可依赖的数值 speed、目标 duration、SSML、词边界或句边界返回字段。**未记载不等于服务绝对不支持；在接口验证前按不具备可靠时间戳处理。**

**[设计]** 定义小型 `TtsProvider` 接口：输入文本、voice、风格；输出音频文件、实际测长、可选边界、供应商请求标识及计量信息。自然语言“稍快”只用于风格，不承担精确对轴。

**[待实验]** 中文自然度、跨请求音色一致性、公式/数字/缩写读法、单次文本上限、并发额度、限流和超时均需实测。初始并发设 1，确认额度后调整为 2 等有限值，429 遵循 Retry-After 和退避策略。

**价格：** 所提供 MiMo 文档没有价格和额度；官方在线文档跳转后未取得可核验正文，因此本计划不填写未经核验的单价，也不假设限时免费长期成立。原型记录音频秒数、文本量、API usage、请求数和重试数，按账号实际计费规则换算每课成本。

**备选：** Azure Neural TTS 仅预留适配器能力，不纳入首版开发，也不更换已指定的 MiMo。其官方 SDK 有 WordBoundary 事件和音频偏移，可在未来需要句词同步时评估；地区、音色、套餐价格和接入成本届时核验。[Azure 合成事件文档](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/how-to-speech-synthesis)

## 6. 新任务数据流与翻译策略

流程：读取已下载视频 → 探测媒体 → 抽取音频 → 英文 Paraformer → 规范化时间轴 → 语义分块 → DeepSeek 翻译 → MiMo 合成 → 固定时间窗对轴 → 字幕同步 → 封装校验 → 发布结果。

### ASR

保留 `transcripts[].sentences[]` 及其 `words[]`、`begin_time/end_time`、原始 JSON，统一转换为整数毫秒。验证时间非负、有序、未超出原视频；无词级信息时降级句级切分，不编造词级精度。无语音、无音轨、坏文件给出明确结果。

上传后立即保存外部 `task_id`，重启优先查询已提交任务，成功后及时落盘结果。超出供应商任务/链接有效期才受控重提；HTTP 超时但可能已提交成功的情况记录为不确定，不能承诺云端请求严格 exactly-once。长课轮询采用可配置总期限和持久化下次查询时间，不照搬旧流程固定等待上限。

Paraformer 当前官方文档与本地旧版在端点和单次 URL 数量上已有差异；新任务每次只提交一个音频 URL，端点沿用有效配置并在原型验证。原型可沿用现有临时上传通道；长期生产音频地址使用稳定 OSS 是独立上线条件，不要求改旧上传流程。[Paraformer 官方接口](https://help.aliyun.com/zh/model-studio/paraformer-recorded-speech-recognition-restful-api)

### 翻译与分块

- 目标 TTS 块约 5–15 秒，优先句末和可听停顿；这是软目标，不能为了凑长度截断单词、公式或语义。
- 每块包含 `block_id`、原文、原始词/句 ID、起止毫秒和上下文；短句可合并，长句在词边界切分。停顿阈值等参数先用样片校准。
- DeepSeek 一次处理多个带 ID 的块，携带相邻上下文及课程术语表，输出结构化 `{block_id, translation, spoken_text}`。验证 ID 集合完整且唯一、无空译文、无截断，错误仅重试本批次。
- `translation` 保存忠实译文；`spoken_text` 允许将数字、公式转成可朗读表达，并在对轴必要时压缩。保存每次版本，配音字幕最终显示实际朗读版本，避免“字幕很完整但声音漏内容”。
- 专业术语、数字、否定、条件和结论不得为缩短时长擅自删除；对压缩版本做结构和关键内容检查，风险块进入质量报告。
- 使用独立提示词文件，课程内容按待处理数据传给模型。首版不强制每块执行双轮润色，优先忠实翻译并仅对超长或异常块追加调用。

## 7. 固定时间轴对轴算法

**[设计]** 以下参数为初始实验值，不是供应商保证。

设原视频时长为 `T`，第 i 块原始语音范围为 `[s_i,e_i]`，下一块起点为 `s_(i+1)`。

1. 验证 `0 <= s_i < e_i <= T`；重叠和零时长块先合并/修正，不能直接生成负窗口。
2. 只借用本块后方的真实空白，计算 `gap_i=max(0,s_(i+1)-e_i)`；最后一块用 `T-e_i`。建议借用上限 1 秒，剩余停顿尽量保留。为下一块保留不超过实际 gap 的小保护间隔，不能向前侵占本块原始讲话范围。
3. 固定允许终点 `b_i=e_i+min(1秒,max(0,gap_i-guard_i))`，保证 `b_i <= s_(i+1)` 且 `b_i <= T`。可用窗口为 `W_i=b_i-s_i`。所有块在合成前确定窗口，后续块起点不随前块结果漂移。
4. MiMo 合成并测量真实有效长度 `d_i`。仅保守处理文件首尾静音，保留辅音和呼吸余量；对块内停顿不做机械删除。
5. 若 `d_i <= W_i`，按自然速度从 `s_i` 放置，余下时间补静音；不强制将短配音拉长到整个窗口。
6. 若 `d_i > W_i`，所需加速为 `r_i=d_i/W_i`。建议可接受上限先取 1.15，使用 FFmpeg `atempo=r_i`，变速后重新测量，不仅依赖理论值。
7. 若超过上限，给 DeepSeek 原文、当前译文、可用时长、术语和保留条件，要求压缩 `spoken_text`，重新合成并测量。最多两轮内容压缩；网络重试另设有界次数，总请求量也有上限。
8. 仍无法容纳则标记 `needs_review`，保存上下文、文本、音频及失败原因，不发布为完整成功，不截掉有声内容、不覆盖下一块、不慢放视频。
9. 按绝对采样位置 `round(s_i * sample_rate)` 放置每块。固定采样率，用整数采样计数生成静音和块边界；按固定窗口输出小段文件后顺序流式拼接，避免整课 PCM 常驻内存或一个数千输入的巨型 FFmpeg 命令。
10. 最后将完整配音轨补齐至原时间轴 `T`，验证无重叠、无越界、无累计漂移，再编码 AAC。若变速结果仅因尾部静音产生极小超差，可裁静音；检测到有声越界则回到失败处理。

例：原块 10–18 秒，下一块 19 秒开始，保护间隔 0.1 秒，则允许窗口 10–18.9 秒。TTS 为 9.5 秒，所需加速约 1.067；调整后再次测长通过才可放置。下一块仍从 19 秒开始。若 TTS 为 12 秒，需要先压缩译文，不能用 1.35 倍直接通过。

算法利用的是原始时间轴中的空白，不试图解决口型同步。FFmpeg 参数能力依据[官方滤镜文档](https://ffmpeg.org/ffmpeg-filters.html#atempo)。

## 8. 字幕同步：明确精度和成本

至少生成三套有明确用途的数据：

- `en.source.vtt`：英文原文，来自英文 ASR 时间轴。
- `zh.source.vtt`：中文忠实译文，依附原文的语义时间窗，用于原声播放。
- `zh.dub.vtt`：最终实际朗读中文，依附调整后的配音时间轴。配音中压缩过的块必须用压缩后文本。

额外生成双语字幕。原声模式在原始时间轴配对；配音模式的英文原文通过块 ID 映射到配音 cue，块内跨语言对应属于语义对齐，不能标为逐词精确同步。

### 推荐实施顺序

1. **首个原型：块级精确边界。** 每次合成对应一个较短语义块，字幕边界直接取该块最终音频实际位置；超长块内可按标点和字数分配显示时间，但必须标注为估算。5–15 秒多句块不能因此宣称句词级准确。
2. **正式首版：验证 Paraformer 二次识别配音。** 对最终采用的块音频按固定批次拼接并保存块偏移，使用同一 Paraformer-v2、`language_hints=["zh"]` 获取句词时间戳；把识别文本与已知 `spoken_text` 做规范化及单调文本匹配，以识别时间匹配已知字幕，绝不直接用识别错字替换译文。换算到块相对时间，再加原视频绝对位置。失败或跨块匹配不可靠时，只重做相应块，或显式回退块级字幕。
3. **[待实验]** 二次识别不等于强制对齐。中文数字、英文缩写和漏字需要匹配门限及人工抽查；门限未通过不能使用伪精确的字数均分时间冒充精确结果。可先识别变速前的最终 TTS WAV，再按已确认的时间变换映射，或直接识别变速后 WAV；原型对比后选择后者作为优先路线，减少换算误差。
4. **后续可选：强制对齐。** 给定 MiMo 音频和已知中文文本，实验支持中文的 CPU 强制对齐器；增加 Python/模型权重、部署时间和 CPU 成本，不作为第一版必须条件，也不假设 WhisperX 的现有依赖已经安装。
5. **若供应商未来确认返回边界：** 统一接口保存原生边界，经过静音裁切、变速、绝对放置的同一变换后生成字幕，优先省去二次识别。Azure 的 WordBoundary 可作为接口设计参考，不意味着本阶段切换供应商。

成本关系：首轮英文 ASR + 翻译及必要压缩 + TTS；启用配音复识别后，额外增加最终中文配音的 ASR 用量和任务等待。按实际语音时长与账号计价统计，不能直接说“费用翻倍”或用整课静音时间估算识别费。

## 9. 播放、下载和媒体封装

### 页面行为

- 原视频下载完成：显示原播放器、“视频翻译”、“下载原视频”和原有删除操作。
- 翻译执行中：显示阶段、完成块数及可解释进度，防止重复提交，原播放器继续可用。状态轮询只更新翻译状态区域，不在每次轮询重建 `<video>`。
- 成功发布：自动将播放器源切为中文配音成品，默认开启配音中文字幕；保存切换前 `currentTime`、播放速率、音量及暂停状态，待新媒体 metadata 就绪再恢复。浏览器不允许自动恢复播放时保留可点击播放态。
- 下载区提供“下载原视频”和“下载翻译视频”；翻译视频尚未发布时隐藏或禁用后者并给出状态。原地址继续指向原文件，不能覆盖。
- 成功后提供“中文配音 / 原声”选择以及字幕选择。切回原声时使用原视频 URL 和原声时间轴字幕；中文模式使用配音 URL 及配音字幕。
- 失败：展示失败阶段及重试入口，继续使用原视频。刷新页面后从服务端恢复翻译状态和默认播放版本。

### 媒体产物

**[设计]** 页面采用两个可选 MP4 源最稳妥：原文件保持不变，新建中文默认音轨成品。不要依赖浏览器原生 `audioTracks` 在所有浏览器切换 MP4 音轨；MDN 标注该能力兼容性有限。[audioTracks 兼容性](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/audioTracks)

“下载翻译视频”对应的同一成品可包含默认中文音轨和备用原英文音轨，方便本地播放器切换；网页原声切换仍通过更换视频源实现。若源音频不能直接封入 MP4，仅对备用音频转 AAC；视频流优先 `-c:v copy`。不兼容的视频编码先报明确限制，再单独评估兼容转码，不能默认在服务器 CPU 上重新编码长视频。

字幕网页使用鉴权后的 WebVTT `<track>`；下载成品可内嵌 `mov_text` 软字幕。WebVTT 更适合页面动态切换，MP4 内嵌字幕方便下载但样式及浏览器显示支持有限；烧录字幕会重编码画面，不纳入首版。

禁止用 `-shortest` 掩盖配音不足而缩短视频。产物先写临时文件，通过 ffprobe 检查视频流、时长、音轨语言/默认标记、字幕及解码可用性，才原子发布。新媒体路由用流式 Range 响应，避免整课文件读入内存；旧视频路由无需为本任务重构。

## 10. 独立状态、恢复和删除一致性

### 状态与缓存

新建独立翻译记录，关联 `source_job_id`、`user_id`，不把原下载状态改成翻译状态。状态建议为 `queued/running/needs_review/succeeded/failed/cancelled/deleting`，另存 stage、完成/总块数、错误、外部任务 ID、版本和时间。

使用独立目录 `./data/pkuvideo_fw_translations/{source_job_id}/{translation_id}/`：

```text
manifest.json             # 状态、源媒体指纹、参数、版本和发布资产
asr/source.raw.json       # 完整英文识别响应
asr/source.normalized.json
translation/blocks.json   # 块、术语、忠实译文与实际朗读版本
tts/{block_id}/...        # 各版本合成、测长、对轴结果
alignment/...             # 配音复识别及时间映射
subtitles/...              # 原声/配音字幕
output/translated.mp4
quality-report.json
```

新增独立文件存储模块，采用串行状态更新、临时写入、原子替换；不重构原 FileStore。缓存键包含源媒体指纹、用户隔离标识、ASR 参数、模型、voice、风格、提示词版本、术语表和文本哈希；修改译文只使相关块及下游产物失效。凭证本身不进入 manifest。

首版假定服务单实例、一个全局长课 worker，云请求有限并发。若将来多实例运行，需单独引入跨进程租约/队列，不声称进程内锁能解决多实例调度。

启动扫描 manifest，校验源任务及文件、清理旧运行租约、恢复已有外部 ASR 查询和已完成块。TTS 已完成但本地未落盘的故障窗口可能造成再次计费，需要记录并限制；保证本地产物幂等，不承诺供应商调用绝不重复。

### 删除原内容和翻译内容

**这是用户明确要求的现有删除动作扩展。** `remove_job()` 保留原有职责并调用新清理模块；手动回放清旧任务复用这个入口，从而覆盖两种视频来源。

1. 在原用户槽位锁保护下，为源任务写入持久化删除标记，拒绝新的翻译提交与结果发布。
2. 请求取消翻译 worker，终止其 FFmpeg/ffprobe 子进程；云端支持取消时尝试取消，否则停止后续查询和本地写回。云端已消耗费用不能通过删除撤销。
3. 等待 worker 释放文件，等待过程中不持有其需要的状态写锁；worker 每次阶段切换和最终发布前都检查取消标记及任务世代。
4. 递归删除经过根目录及任务归属校验的翻译目录、缓存，再删除现有源目录及记录。仅删除该任务的内容，不使用客户端传入的任意路径。
5. 全部成功才返回删除成功；Windows 文件占用等导致失败时保留删除记录和错误，后台/重启后继续清理，页面显示清理中或允许重试，不能报成功后留下文件。
6. 删除期间不允许失败 worker 在任务消失后重建目录；若此时收到云响应，丢弃结果。删除完成后释放任务槽位，保持原有一次一个视频的交互。

所有新增详情、播放、字幕、重试和下载接口都验证 `CurrentUser` 与源任务/翻译记录归属。页面只拿资源 URL，不拿本地绝对路径或密钥。

## 12. 分阶段交付与验收

### 阶段一：最小可验证原型

只对一个已下载视频截取的 2–5 分钟样片运行独立管线，不接入现有生产页面。样片包含术语、数字、长句和明显停顿。

交付完整英文 ASR JSON、带 ID 译文、MiMo 音频、固定窗口对轴报告、三类字幕样本、中文配音 MP4 和实际耗时/计量记录。试听多个中文 voice 后固定一个默认值；对比块级字幕与 Paraformer 中文复识别。对轴参数 5–15 秒、1.15 倍、借用 1 秒、压缩两轮都要用样片评估。

通过条件：能完整走通、画面与速度保留、块无越界和截断、无明显听觉突变、可解释字幕精度、密集块有明确失败记录。只有通过本阶段才接页面和做长课恢复。没有调用真实接口前不承诺时间、价格或准确率。

### 阶段二：页面可用闭环

新增接口和独立持久化，接入“视频翻译”。实现完成自动切中文、原声/字幕切换、两个下载按钮、重试及删除全部产物。先保证用户要求的播放、下载、删除三个动作完整。

验收：刷新能恢复、重复点击不重复创建、翻译失败原视频可用、源切换保存播放位置、下载类型正确、两个来源的视频都可翻译、删除后磁盘无遗留。

### 阶段三：长课与故障恢复

以一节完整课程验证阶段恢复、ASR task_id 恢复、逐块缓存、限流退避、CPU/磁盘/内存边界和删除竞争。首个长课 worker 限制为 1，后续按资源与账号额度扩展。

验收：中途重启不重做已确认完成块；某块失败不会丢失全课结果；运行中删除可终止子进程并阻止结果重建；替换旧手动回放不残留译制文件。

### 阶段四：质量与体验优化

根据实际失败分布决定是否增加精细强制对齐、术语编辑、局部重译或更多音色。首版不预先引入所有方案。

### 必要验证

- 对轴单元验证：短配音、可小幅加速、压缩后合格、仍然超长、零窗口、重叠、长静音和尾块。
- 结构与缓存验证：丢 ID/重复 ID、模型输出截断、TTS 空/损坏 WAV、参数变化只使相关缓存失效。
- 生命周期验证：超时/429、重启、重复提交、删除中云响应回到本地、FFmpeg 占用、清理失败后恢复、越权资源请求。
- 媒体验证：输入输出视频包/帧时间戳与画面一致；封装时长容差先按一帧和编码粒度制定；字幕无负时间/越界。字幕精度目标建议人工标注样本的句边界偏差 p95 不超过 300 ms，需阶段一确认可达性，未达则保留块级说明。
- 页面验证：成功自动切换一次、轮询不重置播放、seek/暂停/倍速保持、字幕与音源匹配、两个下载及删除按钮行为。
- 旧功能回归：原下载成功/失败、单槽位、手动回放替换及原有统一视频处理仍按原设计运行。正式实施时运行适用的 Cargo 检查及相关测试，不为仅新增本计划文档运行业务测试。

## 13. 待确认事项与默认建议

已指定的供应商以及自动显示译制视频、两个下载入口、删除全部内容不再要求重复确认。

实施前主要需要确认两点：

1. **字幕精度与首版范围：** 建议正式首版包含 Paraformer 中文配音复识别；若仍匹配失败，允许明确标注的块级回退。若必须句词级精确且不接受回退，需要先增加强制对齐实验，开发范围会扩大。
2. **极端密集块策略：** 建议超过最大两轮压缩仍不合格时进入待处理，保留原视频和中间结果，暂不发布完整译制视频。是否接受此质量门槛，由用户决定。

音色先按“苏打”开展试听，听感评审后可更换；MiMo 凭证可在原型实施时通过环境变量配置，无需在聊天中提供。实际额度、价格、服务器 FFmpeg 和磁盘可用量是实验/部署检查项，无需先改动现有工作流。
